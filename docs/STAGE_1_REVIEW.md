# Stage 1 review

Stage 1 implements the local Electron workspace and floating companion. Later stages remain unimplemented and need explicit approval.

## Manual review checklist

- [ ] Launch with `npm run dev` and inspect the empty dashboard.
- [ ] Create, rename and delete a course. Confirm before destructive deletion.
- [ ] Import your own PDF, inspect detected topics and compare their page links with the original.
- [ ] Try the optional labelled sample lecture.
- [ ] Open a topic, add notes, rename it, move it, nest it and add a manual subtopic.
- [ ] Use the PDF page controls, zoom and extracted text view.
- [ ] Check the honest placeholders for explanations, lessons, practice and progress.
- [ ] Put another desktop application in front of yoteach; verify Yoyo remains visible.
- [ ] Drag Yoyo by its grip, expand it, preview its states, hide it and restore it from the menu bar or ⌘⇧Y.
- [ ] Switch light/dark/system appearance and try keyboard navigation/reduced motion.
- [ ] Quit with ⌘Q and restart. Check PDF copies, notes, courses, theme, mascot position and continue-learning context.
- [ ] Remove a PDF or course. Confirm the imported copy disappears from yoteach and the original file is untouched.

## Feedback requested

Review the dashboard, roadmap organization, Yoyo's appearance, glass styling and desktop interaction. Revisions stay in Stage 1. Only explicit approval such as “Approve Stage 1; proceed to Stage 2” permits the next stage.

- `npm run build`: passed TypeScript and production bundles.
- `npm test`: all 5 tests passed (storage persistence, validation, PDF ownership/deletion, tree edits and corrupt-file preservation).

- `npm run format:check`: passed.
- `npm audit`: zero reported vulnerabilities across production and development dependencies at verification time.
- Actual Electron captures inspected: empty and populated dashboards, 1280 × 850 and 1000 × 720 desktop windows, light/dark themes, course library, topic workspace, PDF reader and expanded Yoyo panel.

The native file chooser result was supplied by the test harness; this does not replace the real dialog in application code. Test data was isolated from personal documents.

**Not manually verified:** dragging by the grip with the pointer, visibility above a different desktop app, menu-bar restoration by a human, Spaces/full-screen behavior and multiple displays. The Mac was locked and the native automation surface could not unlock it; these checks require the owner to return. Automated checks of the corresponding window flags, movement API and hide/restore passed. No microphone, screen-recording or AI APIs were used.

Screenshots are generated by the test into `.impeccable/review/` and are intentionally not committed. No Stage 2 or Stage 3 functionality has been implemented.
